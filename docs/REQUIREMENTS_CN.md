# facetrack 需求与设计说明

## 1. 目标

独立运行人脸跟踪，不依赖原机器人主工程。模块接收一个或两个同步随颈部转动的普通摄像头画面，选出需要跟随的目标，并可通过已有 ROS 2 Motor 1 协议驱动颈部偏航轴。

## 2. 功能需求

1. 支持一个或两个摄像头，参数可以是摄像头编号或视频路径。
2. 双摄像头时不拼接图像、不做三维标定；每个画面分别检测。
3. 每个摄像头中选择边界框面积最大的人脸，代表当前主要人物。
4. 两个摄像头都有目标时，选择人脸中心在水平方向上偏离画面中心最多的一路。
5. 摄像头切换包含 20% 优势门槛、最小偏差优势、3 帧确认和 0.4 秒保持，避免抖动。
6. 某一路不可用时自动使用剩余一路；两路都不可用时不启动。
7. GUI 只使用 OpenCV，显示画面、框、水平误差、选中的摄像头和电机状态。
8. 默认检测模式绝不发布电机命令。真实控制必须显式传入 `--control`。
9. 真实控制只操作 Motor 1，并限制软件跟踪范围，默认 `-45°` 到 `+45°`。
10. 通过 `/neck_control_owner` 发布短租约，通知遵守相同协议的节点暂停颈部命令。
11. 如果发现其他 `/neck_positions_batch` 发布者，默认拒绝控制；只有确认所有节点都遵守 owner 话题时才可使用 `--allow-coordinated-publishers`。

## 3. 软件环境

### 检测、GUI 与模拟控制

- 64 位 Ubuntu 22.04
- Python 3.10
- USB 摄像头 1–2 个
- CPU 可运行；NVIDIA CUDA 为可选加速

### 真实电机控制

- Ubuntu 22.04
- ROS 2 Humble
- `rclpy` 与 `std_msgs`，由 ROS 2 系统安装提供，不由 pip 安装
- 已运行、并兼容本项目 12 个 float 协议的 CAN/电机桥接节点

本项目不提供 Windows 安装与兼容支持。检测、GUI、模拟控制和真实 ROS 2 控制都在 Ubuntu 环境完成。

## 4. 模型

- 文件：`src/neck_face_tracker/models/yolov8m-face.pt`
- SHA-256：`219f490a97d5722972e1660725fa7cfab54e46c944b833debc28c2302aa1be93`
- 输入尺寸默认 640，可用 `--imgsz` 修改。
- 默认置信度 0.35，可用 `--confidence` 修改。
- 模型随 Python wheel 一起打包，不在运行时联网下载。

## 5. 非目标

- 不做人脸身份识别，不判断人物姓名。
- 不做两个摄像头的画面拼接、深度估计或三维定位。
- 不提供 Web 页面、数据库或云服务。
- owner 话题是节点间协调协议，不是硬实时安全互锁。

## 6. 验收建议

1. 新电脑按对应安装文档创建全新虚拟环境。
2. `facetrack --help` 正常输出，`python -m pytest` 全部通过。
3. 单摄像头检测、双摄像头检测和拔掉一路后的降级行为正常。
4. 使用 `--simulate-motor` 确认跟踪方向与 GUI。
5. 真实硬件首次测试先把跟踪范围改为 `--yaw-min-deg -10 --yaw-max-deg 10 --max-step-deg 2`。
6. 确认急停、机械限位、Motor 1 反馈以及其他发布节点状态后，再扩大范围。
